# Source-question access and disclosure

All 11,107 rows in this release have `source_url` and `source_ref`. Original questions and reference answers appear in 500 [LongMemEval](https://huggingface.co/datasets/xiaowu0162/longmemeval-cleaned) rows, 400 [BEAM 100K](https://huggingface.co/datasets/Mohammadta/BEAM) rows, 200 [BEAM 10M](https://huggingface.co/datasets/Mohammadta/BEAM-10M) rows, and 4,895 [PersonaMem-v2](https://huggingface.co/datasets/bowen-upenn/PersonaMem-v2) rows: 5,995 question/reference pairs in total. BEAM also includes original rubric/event wording and saved judgment reasons. Those 4,895 PersonaMem rows include the preserved option string and correct option letter.

The 1,540 [LoCoMo](https://github.com/snap-research/locomo/blob/main/data/locomo10.json) rows and 3,467 [HaluMem Medium](https://huggingface.co/datasets/IAAR-Shanghai/HaluMem/blob/main/HaluMem-Medium.jsonl) rows omit source question/reference text and GPT answer bodies. They provide saved scores, official source links, locations, and `answer_disclosure`. For this business/product-purpose release, the 5,007 rows in these two NC-marked datasets were limited because answers could repeat source wording. Original answers remain in private source records. The official source links can help locate benchmark questions; they do not contain Tenconic's generated answers. Saved-score arithmetic remains reproducible, but answer bodies cannot be reviewed here. Another 105 PersonaMem rows omit question, reference, and choices because the source wording contained provider-key-like or private-path-like patterns. This does not establish that real credentials or private paths exist. In total, 5,112 rows use source link/location instead of question/reference wording. Saved GPT answers and correctness scores remain for all 5,000 PersonaMem rows. No panel bundles original conversations, retrieved context, full model inputs, or dataset evidence content.

| Panel | How to locate the question in the official source |
| --- | --- |
| `locomo` | In `locomo10.json` at `source_url`, select conversation `source_ref.conversation_index0`. Cross-check conversation ID using `sample_id`, then select `qa` entry `original_qa_index0`. `json_pointer` is `/{conversation_index0}/qa/{original_qa_index0}`; `evaluated_qa_index0` locates the evaluated row. |
| `halumem` | In `HaluMem-Medium.jsonl` at `source_url`, find the record whose original `uuid` equals `source_ref.user_uuid`. Select its `sessions[session_index0]` then `questions[question_index0]`. `json_pointer` is `/sessions/{session_index0}/questions/{question_index0}` **within that JSONL record**. |
| `lme` | Use `row_index0` together with `question_id` to cross-check the cleaned S source row. Also compare published `question` and `reference_answer`. |
| `beam100k`, `beam10m` | Find `conversation_id` in their distinct `source_url` values. `question_index0` follows the evaluation parser's flattened dimensional question order; cross-check published `category` and `question` against the original. Do not treat 100K and 10M as one source file. |
| `personamem` | Use `csv_row_index0` to locate the original text 32K CSV row. For 4,895 published rows, `choices` preserves saved `all_options` order and string formatting and `reference_answer` is the correct option letter. The 105 restricted rows have `source_disclosure`; use the same `source_url` and CSV row location. Find the text 32K material from the official dataset page. |

Indices start at zero. These identifiers address saved evaluation-time inputs; they are neither immutable upstream revisions nor proof of original-file integrity. If upstream data changes, the same index can refer to another item. Cross-check UUID, question ID, sample ID, and published question text where available; do not treat a mismatch as the same source.
